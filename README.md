# 銘板照合 PoC Webアプリ

出荷前の銘板をカメラ映像でリアルタイムにOCR・照合し、**PASS / NG** を完全自動で判定する
PoC（概念実証）用の Web アプリです。映像検査に加えて、画像アップロード・撮影画像OCRの
手動検査にも対応します。

- フレームワーク: React + TypeScript + Vite
- OCR: [Tesseract.js](https://github.com/naptha/tesseract.js)（`jpn+eng`、永続ワーカー方式）
- カメラ: `navigator.mediaDevices.getUserMedia`（背面カメラ）
- 画像処理: [OpenCV.js](https://docs.opencv.org/)（銘板の輪郭検出のみ。CDN読込・任意）
  ＋ 素の canvas 処理（前処理・行分割）
- スタイル: 素の CSS（レスポンシブ対応、iPhone / iOS Safari 利用可）

**映像検査の構成（負荷分離）**

- 映像表示・輪郭検出ループ：約 **30FPS**（`requestAnimationFrame`）
- OCR検査ループ：約 **2FPS / 500msごと**（`setInterval`、多重実行防止つき）

2つのループは独立しており、OCRが重くても映像が固まりません。映像（30FPS）と
OCR結果（2FPS）は更新タイミングが異なるため、**画面上の輪郭・行帯とOCR判定には
わずかなズレが出ます**（仕様）。

## 画面構成（上から順・iPhone 1画面想定）

1. **ヘッダー**：タイトル「PlateChecker」＋右端に**設定（歯車 ⚙）アイコン**。歯車を押すと
   設定メニューが**オーバーレイ（モーダル）**で開きます（画面レイアウトは押し広げません）。
2. **映像枠（横長）＋検出枠（赤）**：カメラ映像。**ガイド枠は赤**。検出輪郭（緑）・行帯（水色）の
   位置情報のみ描画し、**銘板の記載内容・判定情報は映像上に重ねません**。映像**右上**に直近の
   読み取り結果を**ラベル付き2段**で控えめに表示します。
   - 1段目（`OCR: `）：直近にOCRが読み取った生テキスト（1〜2行・例 `OCR: M1・M3棟 電灯`）。
   - 2段目（`照合: `）：照合対象の文字列＋類似度（例 `照合: M1・M3棟 電灯 38%`）。
3. **最小ステータス（1行）**：`CV✓・行3・自動` のように短く集約（OpenCV状態・検出行数・モード）。
4. **操作行（横並び1行）**：`[モード切替ボタン] [行数セレクト] [検査開始/停止・リセット]` を
   **折り返さず横1行**に配置します。
   - モード切替ボタンのラベルは **「自動(切替)」「固定(切替)」**（半角括弧）。
   - 行数は **1〜4 のセレクトボックス**で指定（**固定モード時のみ表示**）。自動モード時は非表示ですが
     **領域（幅・高さ）は確保**するため、自動↔固定の切替でレイアウトが揺れません。
   - 検査開始ボタンは**行数セレクトの右端**に配置。検査中は「リセット」「停止」に切り替わります。
5. **検査ガイド（折りたたみ）**：検出枠を中心固定で伸縮する「幅」「高さ」スライダー（**px指定**：
   5px刻み・最小は幅100px×高さ50px・最大は映像枠の表示実寸に追従）。映像枠の直下にあるため、開いて
   スライダー調整中も映像枠（検出枠）が見えます。
6. **検査データ：製番→種類の2段階選択**：製番プルダウン → 種類プルダウン →「セット」。
7. **検査内容テーブル（固定高さ＋スクロール）**：`No / 行数 / 記載内容 / OCR / 検査数`。
8. **結果出力・手動検査（折りたたみ・退避）**：検査結果JSONダウンロード／画像アップロード・撮影OCR。

> 1画面化のため、検査結果JSONダウンロードと手動検査は**折りたたみに退避**し常時表示しません
> （機能は維持）。ステータスは1行に最小化しています。

## 使い方

1. `npm run dev` で起動（`https://localhost:5173`、証明書警告は許可）。
2. **製番を選ぶ**と、その製番にぶら下がる**種類**が選べるようになります。種類を選び **「セット」**。
   セットした種類のすべての銘板(No)が検査内容テーブルに表示され、各Noの**検査数**（必要枚数）が
   `0/quantity` で初期化されます。
3. 操作行の **「検査開始」** を押し、カメラ使用を許可する。
   - 初回は Tesseract 言語データと OpenCV.js のダウンロードに時間がかかります（後述）。
4. 銘板を映像中心の**検出枠**に収める。輪郭が検出されれば緑枠の領域、検出できなければ
   検出枠（ガイド枠）がそのままOCR領域になります（フォールバック）。検出枠サイズは
   「検査ガイド」を開いて**px単位**（5px刻み・最小は幅100px×高さ50px・最大は映像枠の表示実寸）で
   調整できます（現在値は「幅 320px」のように表示。映像を見ながら調整可能）。
5. **行検出モードを選ぶ**。「自動(切替)／固定(切替)」ボタンで切り替え、固定モード時のみ
   右側に**行数(1〜4)のセレクトボックス**が表示されます。
6. 検査は自動で回り続けます。**登録順に依存せず、一致した行から順不同で消し込み**ます。
   行ごとに一度PASSが出たら確定（再評価しない）し、テーブルの **OCR列に ○** が付きます。
   映像右上には、処理ごと（2FPS）に最新のOCR生テキストと類似度が更新表示されます。
7. **全行が消し込まれると「1枚OK」**として、その No の**検査数がカウント**されます（例: `1/3`）。
   必要枚数に達すると次の No へ自動で進みます。
8. **すべての No が必要枚数に達すると「全数検査完了」**が映像下のステータスに表示されます。
9. 「結果出力・手動検査」を開いて **「検査結果JSONをダウンロード」**（製番単位：各Noの判定・枚数・
   行ごと照合）を出力できます。

> **検査数の見方**：`1/3` は「同じ銘板3枚のうち1枚OK」。`0/1` は「1枚必要で未OK」。
> 1枚OKになるたびにカウントアップし、次の1枚に向けてその No の行OKはリセットされます。

> **OKが出続けない行は確定されません**。これは誤検出による誤OKを避けるための仕様で、
> 確定しない行は目視検査へ回す運用を想定しています（連続Nフレーム判定は行いません）。

### 自動モードと固定モードの違い・使い分け

| モード | 行の決め方 | 向いている場面 |
| --- | --- | --- |
| **自動** | グレースケール画像の水平投影（行ごとの暗い画素の塊）から行を自動分割 | 行間が空いていて行が分離しやすい銘板。まず自動で試す。 |
| **固定** | 領域の縦を指定行数で等分し、各帯を1行として扱う | 行が詰まっている／自動でうまく割れない銘板。**期待値の行数に合わせる**と対応が安定。 |

> 自動モードの行検出は、グレースケール画像に対して**行検出の投影にのみ**内部でしきい値（Otsu）を求め、
> 暗い画素を文字として数えます。行検出は前処理設定（二値化ON/OFF等）に左右されない**安定グレースケール**で
> 行うため、前処理を変えても行分割が壊れません。

### OCR前処理（設定フォームの値で実適用）

OCRに渡す画像の前処理は **`src/logic/preprocessPipeline.ts` のパイプライン**で行い、**設定メニューの
前処理フォームの値で実際に適用**されます（上の「前処理設定フォーム」節を参照）。

- 適用順・対象項目・OpenCVフォールバック・行検出の安定化は前述のとおり。**デフォルトは `threshold` 有効**
  （初期から二値化）。照明ムラ・反射で潰れる場合は設定で `threshold` を「なし」にして調整します。
- **OCR入力の解像度・範囲・アスペクト比は前処理では変えません**。検出枠／輪郭から切り出した領域を
  元解像度のまま前処理し、行ごとの `resize` も `keep_ratio` で縦横比を保ちます（縦横独立の拡縮はしない）。
  表示用プレビューの縮小（約360px化・10FPS間引き）は**表示側だけ**に閉じ、OCR入力には波及しません。
- カメラは `width/height: { ideal: 1920×1080 }` を要求し（非対応端末はフォールバック）、入力解像度を確保します。
- **適用範囲**：映像検査は領域切り出し → 行検出（安定グレー）→ 領域前処理（`preprocessRegion`）→
  行ごと仕上げ（`finishBandCanvas`：deskew/crop_margin/resize）→ 行ごとOCR。手動検査（アップロード/撮影）は
  従来どおり画像をそのまま Tesseract に渡します（このパイプラインは通りません）。

### OCR入力のアスペクト比保持（圧縮潰れの修正）

OCRに渡す切り出し画像は、**検出枠内の座標・アスペクト比そのまま**で渡します（縦横独立の拡縮はしません）。

- 領域の切り出し（`runOcrCycle` の frame canvas）は、元領域 `region.width×region.height` を**同寸の canvas**へ
  描画します。行ごとの `resize`（`finishBandCanvas`）も `keep_ratio` で**縦横同一の倍率**で拡縮します。
  **縦横比を歪めるリサイズや、縦横独立の拡縮は行いません**。
- 以前は、検出枠・行帯のオーバーレイと「前処理後映像」プレビューを `sx=cw/vw, sy=ch/vh`（＝映像を枠いっぱいに
  引き伸ばす想定）の**線形マッピング**で描いていました。映像は CSS `object-fit:cover` で表示しているため、
  **カメラのアスペクト比が表示枠(16:9)と異なると `sx≠sy` となり、プレビューが縦に圧縮**され、通常映像とも一致
  しませんでした（OCR結果が大きく崩れて見える一因）。
- 修正後は、オーバーレイ／プレビュー canvas の**バッキングストアを映像の実ピクセル(`videoWidth×videoHeight`)**にし、
  **映像ピクセル座標のまま**描画して、表示は映像と同じ **`object-fit:cover`** に任せます。これにより手動の `sx/sy`
  拡縮を排除し、**任意のカメラ比率でも歪まず、通常映像・検出枠・前処理後映像・OCR入力の範囲とアスペクト比が一致**します。

## 設定メニュー（歯車 ⚙ ／ オーバーレイ）

ヘッダー右端の**歯車アイコン**から設定メニューを開きます（オーバーレイ。背景クリックまたは×で閉じます）。

- **表示位置は画面下寄せ（ボトムシート）**で、背景を暗くしません。これにより**映像枠（画面上部）に
  被らず、映像と設定メニューが同時に見えます**。前処理後映像の表示を見ながら値を調整できます。
- パネルは高さを制限し（`max-height`）、**項目が多くてもパネル内をスクロール**して操作できます。
  見出し（設定／×）はパネル上部に固定（sticky）です。
- オーバーレイのまま本体レイアウトを押し広げない・揺らさない設計は維持しています。

### 通常映像／前処理後映像の切替（Switch）

設定メニュー内の **Switch（トグル）** で、映像枠に映す内容を切り替えます。

- **OFF（既定）＝通常映像**：カメラ映像をそのまま表示。
- **ON＝前処理後映像**：OCRが実際に処理しているのと**同じ切り出し領域だけ**に、**同じ前処理**
  （グレースケール＋軽いコントラスト補正。二値化はしない）をかけた結果を表示します。領域外は通常映像が
  透けて見えるため、**「OCRがどの範囲を・どんな見た目で食べているか」** がそのまま分かるデバッグビューです
  （検出枠・行帯のオーバーレイはその上に重なります）。

> **この切替は「表示」だけの切替で、OCRに渡る画像やOCR処理自体は一切変わりません。**
> 表示＝OCR入力となるよう、**範囲（切り出し領域）と前処理パイプライン（`src/logic/preprocessPipeline.ts` の
> `preprocessRegion`）はOCRと共通**です（`src/hooks/useVideoInspection.ts` の `runOcrCycle` と `drawPreprocessed`）。
> 表示は表示ループ側（30FPS）で**約10FPSに間引き**、かつ表示用に領域を縮小して処理します。
> **この縮小は表示専用で、OCR入力には波及しません**（OCRは領域を元解像度のまま処理）。
> よって 30FPS表示／2FPS検査の負荷分離を崩さず、映像もカクつきにくくしています。

### 前処理設定フォーム（値を実際の前処理に適用）

設定メニュー内に、OCR前処理パラメータを編集する**フォーム**があります。

- **フォームの値は、OCRに渡る画像の前処理に実際に適用されます。** 全項目（`threshold` / `clahe` /
  `sharpen` / `gamma` / `morph` / `unsharp` / `bilateral` / `local_contrast` / `crop_margin` /
  `hist_equalize` / `stroke_boost` / `denoise` / `deskew` / `resize` および `ratio_threshold`）を実装。
- **変更は即時反映**：OCRに渡る前処理（2FPS検査ループ）と、設定メニューの「前処理後映像」表示の
  **両方に同じパイプライン**（`src/logic/preprocessPipeline.ts`）が適用されます。映像を見ながら値を追い込めます。
- **OCRの切り出し範囲・座標・アスペクト比は変えません。** 変わるのは「切り出した画像にかける前処理」だけです。
- 各項目を**個別のUIコントロール**でフォーム化：数値（数値入力）／トグル（ON/OFF スイッチ）／セレクト（選択肢）。
  **ラベル・選択値は日本語表示**（例：`threshold`→「二値化」、`binary`→「二値」、`close`→「クローズ」、
  `gaussian`→「ガウシアン」）。**内部で保持する値・キー・型は英語のまま**（`preprocess.operations.*`）。
- **設定メニュー最下段の「デフォルト値に戻す」**ボタンで全項目を既定値へリセットできます。
- 設定値は**設定メニューを閉じても保持**されます（セッション中は値が失われず、再度開くと同じ状態。
  App の state で保持。リロードでの永続化は対象外）。
- 値は `types.ts` の **`PreprocessSettings` 型**で保持し（デフォルトは `src/logic/preprocessSettings.ts` の
  `DEFAULT_PREPROCESS_SETTINGS`）、依頼JSONの `preprocess` 構造に1:1で対応します。フォーム本体は
  `src/components/PreprocessSettingsForm.tsx`。
- フォームが増えても**本体レイアウトは揺らしません**。設定はオーバーレイのままで、項目が多い場合は
  **オーバーレイ内でスクロール**します（`.settings-panel { max-height; overflow-y:auto }`）。

**適用順序（パイプライン）**：グレースケール → `denoise` → `bilateral` → `clahe` → `local_contrast` →
`hist_equalize` → `gamma` → `sharpen` → `unsharp` → `morph` → `stroke_boost` → `threshold`（以上は
領域レベルで幾何を変えない）→ 行(バンド)ごとに `deskew` → `crop_margin` → `resize`（`keep_ratio`：
縦横比を歪めない）。`ratio_threshold` は行の縦横比で `resize` 高さを `single`/`wide_height` に切替える分岐に使用。
`clahe`・`bilateral`・`morph` 等は OpenCV.js を利用し、**未ロード/失敗時は素のグレースケール＋JS可能分へ
フォールバック**して検査を止めません。行検出は前処理設定に左右されない**安定グレースケール**上で行います。

> **デフォルトは `threshold` 有効（初期から二値化）**。影・反射で文字が潰れる場合は、設定メニューで
> `threshold` の種別を「なし」にする（または値を調整する）と二値化を外せます。

保持する前処理パラメータ（`preprocess`）の構造とデフォルト値：

| 項目 | パラメータ（既定値） |
| --- | --- |
| `ratio_threshold` | `1.6` |
| `threshold` | `type: binary`, `value: 70` |
| `clahe` | `clip_limit: 1`, `tile_grid_size: 2` |
| `sharpen` | `enabled: true`, `amount: 0.2`, `sigma: 0.5` |
| `gamma` | `enabled: false`, `value: 1` |
| `morph` | `enabled: false`, `method: close`, `ksize: 3`, `iterations: 1` |
| `unsharp` | `enabled: false`, `amount: 0.8`, `radius: 1`, `threshold: 0` |
| `bilateral` | `enabled: false`, `diameter: 5`, `sigma_color: 50`, `sigma_space: 50` |
| `local_contrast` | `enabled: false`, `clip_limit: 2`, `tile_grid_size: 8` |
| `crop_margin` | `enabled: false`, `threshold: 245`, `margin: 2` |
| `hist_equalize` | `enabled: false` |
| `stroke_boost` | `enabled: false`, `method: close`, `ksize: 1`, `iterations: 1` |
| `denoise` | `method: gaussian`, `ksize: 1` |
| `deskew` | `enabled: false` |
| `resize` | `single: 48`, `wide_height: 48`, `keep_ratio: true` |

> セレクトの候補：`threshold.type`＝`binary / binary_inv / otsu / adaptive / none`、
> `morph.method`・`stroke_boost.method`＝`close / open / dilate / erode`、
> `denoise.method`＝`gaussian / median / bilateral / none`（現値を含む妥当な候補）。

## 画面を揺らさないための設計（重要）

銘板の行数（1〜4）やモード切替で**レイアウトの縦方向の高さが変動しない**よう設計しています。

- **検査内容テーブルは固定高さ**（`height` 固定＋`overflow-y:auto`）。行が増えても領域の高さは不変で、
  中身だけが縦スクロールします（ヘッダーは sticky）。
- **操作行は横並び1行で折り返さない**（`flex-wrap:nowrap`）。各要素（モード切替・行数セレクト・
  検査開始）の幅・余白を抑え、iPhone幅でも1行に収まるようにしています。
- **行数セレクトは非表示時も領域の幅・高さを確保**（`visibility:hidden` で占有を維持）。
  自動↔固定の切替で他要素が動きません。操作行は `min-height` 固定です。
- **設定メニューは画面に固定のオーバーレイ（`position:fixed`）**で開くため、開閉しても本体の
  レイアウトを押し広げません（背景クリック／×ボタンで閉じる）。
- **映像枠は `aspect-ratio:16/9`** で高さが中身に依存しません。ステータスは `min-height` 固定の1行。
- **映像右上のオーバーレイ（`OCR: 〜` / `照合: 〜 %` のラベル付き2段）は固定高さ**。生テキストは
  最大2行で省略、照合行（類似度）は1行で省略するため、文字の長短・桁数が変わっても領域の高さは
  変動しません。行頭ラベルは短い固定文字列のため領域を広げません。映像枠内に絶対配置しているため
  レイアウト自体を押し広げません（更新は2FPSの検査ループに同期）。
- iOS Safari のアドレスバー伸縮・セーフエリア対策として `env(safe-area-inset-*)` を考慮しています。

### iPhone 1画面化の方針

- **検査結果JSONダウンロードボタン**と**手動検査（アップロード/撮影）**は「結果出力・手動検査」の
  折りたたみへ**退避**（機能は維持、常時は非表示）。
- **ステータス文言を1行に最小化**（OpenCV状態・検出行数・モードを短く集約）。
- **検査ガイド（幅・高さスライダー）は折りたたみ**。ただし映像枠の直下に配置しているため、
  **開いて調整するときも映像枠（検出枠）が同時に見え**、枠の伸縮をリアルタイムに確認できます。

> 1画面に完全に収め切ること（全くスクロールさせないこと）より、「高さ固定＋スクロール」で
> 揺れを根絶することを優先しています。**最終的な収まりは実機で確認・調整する前提**です。

映像検査とは別に、従来どおりの静止画検査も画面下部の「結果出力・手動検査」折りたたみから
利用できます。セット済みの製番/種類の**銘板(No)を選び**、画像アップロード／撮影して照合します。

## 回答データ JSON の形式（製番 → 種類 → 銘板）

`public/sample-answers.json` を編集すると、照合に使う正解データを差し替えられます。
**製番(`serialNumber`) に複数の種類(`types[]`) がぶら下がり、各種類が複数の銘板(`nameplates[]`)、
各銘板が行リスト(`labelTexts`)と枚数(`quantity`)を持つ**入れ子構造です。

```json
{
  "products": [
    {
      "serialNumber": "S-2024-001",
      "types": [
        {
          "type": "汚泥ポンプ棟 動力盤",
          "nameplates": [
            { "labelTexts": ["<PW-1-1>", "No.1,2汚泥ポンプ棟", "建築動力"], "quantity": 3 },
            { "labelTexts": ["200V変圧器1次"], "quantity": 1 }
          ]
        },
        {
          "type": "汚泥ポンプ棟 制御盤",
          "nameplates": [
            { "labelTexts": ["No.1ポンプ", "No.2ポンプ"], "quantity": 1 }
          ]
        }
      ]
    }
  ]
}
```

| キー | 意味 |
| --- | --- |
| `serialNumber` | 製番 |
| `types[]` | その製番にぶら下がる種類のリスト（製番プルダウン→種類プルダウンに対応） |
| `types[].type` | 種類 |
| `types[].nameplates` | その種類の銘板(No)のリスト。配列順に No.1, No.2, … |
| `nameplates[].labelTexts` | その銘板の行ごとの期待値（各要素を1行としてOCR照合） |
| `nameplates[].quantity` | 同一銘板の枚数（検査数）。省略時は `1` |

上記の「汚泥ポンプ棟 動力盤」は「No.1＝3行で3枚（検査数 `0/3`→`3/3`）、No.2＝1行で1枚（`0/1`）」を表します。

**後方互換**（いずれも内部で上記の製番→種類→銘板へ正規化）：

- 旧 `{ plates: [ { serialNumber, type, nameplates|labelTexts } ] }`（製番＋種類が並列）→
  同一 `serialNumber` を1製番にまとめ、`type` ごとに `types[]` へ集約。
- 旧 `{ serialNumber, type, labelTexts }`（単一銘板）→ `quantity:1` の1銘板として読込。
- 配列 `[ {...}, {...} ]`、`{ products:[...] }`、`quantity` 省略(=1) も可。

> 別ファイルを参照させたい場合は `src/services/answerDataService.ts` の
> `loadProducts(url)` に任意の URL を渡せます（将来 API/DB 化する際の差し替え口）。

### 検査結果 JSON（ダウンロード形式）

映像検査は**製番単位**（複数銘板）で出力します。

```json
{
  "serialNumber": "S-2024-001",
  "type": "汚泥ポンプ棟 動力盤",
  "checkedAt": "2026-06-25 10:30",
  "result": "PASS",
  "nameplates": [
    {
      "no": 1,
      "quantity": 3,
      "passedCount": 3,
      "result": "PASS",
      "matches": [
        { "expected": "建築動力", "ocrCandidate": "建築動力", "status": "PASS", "score": 1.0 }
      ]
    }
  ]
}
```

手動検査の「この結果JSONをダウンロード」は、従来どおり**1銘板分**（`serialNumber`/`type`/`result`/
`matches` を持つ形）を出力します。

## OCR 設定の変更方法（ホワイトリストはソースのみ）

OCR の初期値は **`src/services/ocrService.ts` の定数 `DEFAULT_OCR_OPTIONS`** で定義しています
（手動・映像検査で共通の唯一の参照元）。**ホワイトリストを含む OCR 設定の編集UIは廃止**したため、
変更はこの定数（`DEFAULT_OCR_OPTIONS.whitelist` 等）を直接編集してください。

| 設定 | 内容 | 初期値 |
| --- | --- | --- |
| `lang` | 認識言語（Tesseract 言語データ名） | `jpn+eng` |
| `psm` | Page Segmentation Mode。`6`=均一なブロック / `7`=単一行 | `6` |
| `whitelist` | 認識を許可する文字（`tessedit_char_whitelist`）。空文字で無制限 | `DEFAULT_OCR_OPTIONS.whitelist` 参照 |

### ホワイトリストの適用経路（重要）

`DEFAULT_OCR_OPTIONS.whitelist` は次のように**映像検査・手動検査の両経路**で OCR に渡ります。

- 手動検査：`App` の `ocrOptions`（= `DEFAULT_OCR_OPTIONS`）→ `ManualInspection` →
  `ocrService.recognize(image, ocrOptions)`。
- 映像検査：`App` → `useVideoInspection(target, ocrOptions, …)` → 行ごとに
  `ocrService.recognize(canvas, opts)`（`opts` は `ocrOptions`）。

`recognize` 内では `tessedit_char_whitelist` と `psm` を **ワーカー生成直後**と**各認識の直前**の
両方で `setParameters` により適用します（永続ワーカーを使い回しても確実に効くようにするため）。
`lang` は `setParameters` ではなく **`Tesseract.createWorker(lang, …)` の生成時引数**として渡します
（言語データはワーカー生成時にロードされるため）。`lang` が変わったときだけワーカーを再生成します。

> ホワイトリストにある文字（例 `棟`）は読み取られ、外した文字は出力されません。動作確認時は
> `DEFAULT_OCR_OPTIONS.whitelist` から特定文字を抜く／加えると、フィルタが効いていることを
> 両経路で確認できます。

### 日本語認識と言語学習データ（jpn+eng）

- **言語設定は `DEFAULT_OCR_OPTIONS.lang = 'jpn+eng'` の1か所のみ**に集約しており、映像検査・
  手動検査の両経路がこの同じ値を使います（上記「ホワイトリストの適用経路」と同じ流れ）。
  これにより日本語（漢字・カナ）と英数字の両方が認識候補に入ります。`jpn` が抜けて `eng` のみに
  なると漢字・カナが取りこぼされるため、変更時はこの定数だけを編集してください。
- **取得元（langPath）**：`src/services/ocrService.ts` の定数 `OCR_LANG_PATH` で指定します。
  既定は `undefined` で、tesseract.js が **jsDelivr CDN**
  （`https://cdn.jsdelivr.net/npm/@tesseract.js-data/<lang>/4.0.0`）から `jpn` / `eng` の
  `*.traineddata` を取得します。社内ネットワーク等でCDNに出られない場合は、`jpn.traineddata.gz` /
  `eng.traineddata.gz` を配置したベースURL（例: `'/tessdata'`）を `OCR_LANG_PATH` に設定すれば
  取得元を差し替えられます。
- **初回ロード時間**：`jpn` の学習データは数MB〜十数MBあり、**初回のみダウンロードに時間がかかります**
  （以降はブラウザの IndexedDB にキャッシュされ高速化）。映像検査では「検査開始」時に
  ワーカーを**事前ロード（warm-up）**し、初回OCRの待ち時間を短縮します。
- **失敗時の挙動**：tesseract.js は `jpn` データの取得に失敗した場合、英語のみへ自動フォールバック
  **せず例外**になります。本アプリは `createWorker` の `errorHandler` と事前ロードでこれを捕捉し、
  **最小ステータス行に `OCR言語データ読込失敗: …` と表示**して原因を可視化します（映像表示自体は継続）。
  手動検査側では OCR 実行時のエラーとして表示されます。

### 正規化・誤認識補正の辞書

OCR 結果と期待値は照合前に正規化されます（`src/logic/normalize.ts`）。

- 全角英数字 → 半角
- **半角・全角スペース、タブ、改行の除去**（例: `3棟 200V動力` → `3棟200V動力`）
- 比較に不要な記号の除去
- **文字置換辞書** `REPLACEMENT_DICTIONARY` による補正（例: `髙` → `高`）

誤読・異体字の補正ルールは `REPLACEMENT_DICTIONARY` に `"誤": "正"` を追記するだけで増やせます。

### 照合の閾値・判定

`src/logic/match.ts` の `DEFAULT_THRESHOLDS.reviewThreshold`（初期値 `0.8`）で
「要確認」と判定する類似度の下限を調整できます。

- 完全一致 / 部分一致（包含関係で一致） → **PASS**
- 類似度が閾値以上 → **要確認 (REVIEW)**（手動検査のみ）
- 類似度が閾値未満・未検出 → **NG**

手動検査の総合判定は「1件でも NG → NG、NG なしで REVIEW あり → 要確認、全件 PASS → PASS」。
**映像検査**では「行ごとに一度でも **PASS** が出たら確定（OK）」とし、全行確定で全体OK
（確定しない行は NG 扱い＝目視検査へ）。類似度は簡易にレーベンシュタイン距離から算出しています。

## OpenCV.js について（読み込み方法・サイズ・初期化待ち）

銘板の**輪郭検出**にのみ OpenCV.js を使用します（前処理・行分割は OpenCV 非依存の
`src/logic/vision.ts` で実装）。

- **読み込み方法**：CDN（`https://docs.opencv.org/4.10.0/opencv.js`）から `<script>` で
  動的読み込みします（`src/services/opencvService.ts`）。npm 同梱はせず、**映像検査を開始した
  ときに初めて**ダウンロードします。
- **サイズ・初回**：OpenCV.js は数MB と大きく、**初回はネットワーク接続が必要**です。
  ダウンロード後に WASM の初期化完了（`onRuntimeInitialized`）を待ってから輪郭検出が有効化されます。
  画面の「OpenCV: 準備完了 / 読込中」で状態を確認できます。
- **失敗時**：読み込み・初期化に失敗しても**アプリは止まりません**。輪郭検出なしで、
  後述のガイド枠をそのまま OCR 領域として検査を継続します。
- オフライン運用したい場合は、`opencv.js` を `public/` に配置して `OPENCV_URL` をローカルパスに
  変更してください（`opencvService.ts` の1か所）。

## 輪郭が取れない場合のフォールバック（ガイド枠の伸縮）

銘板の四角形輪郭が検出できない場合は、**映像中央のガイド枠をそのまま OCR 領域**として使います。
このときに枠を合わせられるよう、ガイド枠は**中心固定のまま幅・高さをスライダーで伸縮**できます。

- 「幅」「高さ」スライダー（**px単位**：5px刻み・最小は幅100px×高さ50px・最大は映像枠の表示実寸に追従）で、
  中心点を軸に上下・左右へ対称に伸縮します。指定pxは**映像枠上で見えている実寸**を基準とし、
  OCR切り出し用の実映像解像度との換算は内部で吸収します（指定px＝映像枠で見える範囲）。
  画面幅・回転で映像枠の実寸が変わると、スライダーの最大値も追従します。
- 銘板が枠からはみ出す／余白が多すぎる場合に調整してください。
- 検出行数が期待と合わないときは、**固定モード＋行数指定**と併用すると安定します。

## iPhone でカメラを使う手順（HTTPS 必須）

iOS Safari のカメラ API（`getUserMedia`）は **HTTPS（または `localhost`）でしか動作しません**。
iPhone から PC の開発サーバーへ LAN 経由で `http://` アクセスするとカメラは起動しません。
本プロジェクトは `@vitejs/plugin-basic-ssl` により開発サーバーを **HTTPS 化済み**です。

### 手順（LAN 経由で iPhone の実機検証）

1. PC とiPhone を**同じ Wi-Fi（同一 LAN）**に接続する。
2. PC の IP アドレスを確認する。
   - Windows: `ipconfig` の「IPv4 アドレス」（例: `192.168.1.23`）
   - macOS: `ipconfig getifaddr en0`
3. 開発サーバーを LAN 公開で起動する。
   ```bash
   npm run dev -- --host
   ```
   起動ログの `Network:` 行に `https://<PCのIP>:5173/` が表示されます。
4. iPhone の Safari で **`https://<PCのIP>:5173`** を開く（`http` ではなく必ず `https`）。
5. **自己署名証明書の警告**が出るので、「詳細を表示」→「この Web サイトを閲覧」→
   「Web サイトを閲覧」の順で**手動で許可**する。
6. **製番・種類を「セット」**してから、映像枠下の「検査開始（カメラ起動）」をタップし、
   カメラ使用を**許可**する。（静止画で確認する場合は最下部「手動検査」の折りたたみも使えます）
7. 検出枠内に銘板を収めると、自動で行ごとにOCR・照合され、テーブルのOCR列に○・検査数がカウントされます。

### うまくいかないとき

- **カメラが起動しない / 真っ黒**：URL が `https` か、証明書を許可したかを確認。
  Safari の「設定 → Safari → カメラ」や、サイトごとの許可設定も確認してください。
- **証明書を許可しても弾かれる**：iOS のバージョンによっては自己署名証明書を嫌う場合があります。
  その場合は `npm run build` した `dist/` を、信頼された証明書を持つ **HTTPS ホスティング**
  （社内サーバー、ngrok、Cloudflare Tunnel、各種静的ホスティング等）に配信して検証してください。
- **PC（localhost）での確認**：`https://localhost:5173` はカメラを利用できます（証明書警告は許可）。

> カメラが使えない環境でも、**画像ファイルのアップロード経路は常に利用可能**です
> （カメラ非対応・不許可時は自動的にその旨を表示し、アップロードにフォールバックできます）。

### iOS Safari 向けに実装している対策

- `<video>` に `playsInline` / `muted` を付与（インライン再生・自動再生のブロック回避）。
- カメラ起動は**ユーザー操作（ボタンタップ）を起点**にしている。
- 使い終わったメディアストリームは `track.stop()` で解放（`useCamera` フック / `cameraService`）。
- レスポンシブ対応（狭幅でレイアウト非破壊、ボタン最小 44px、テーブルは横スクロールコンテナ）。

## ローカル実行時の注意点（Tesseract.js 言語データ）

- Tesseract.js は初回認識時に **言語データ（`jpn.traineddata` / `eng.traineddata`）を
  CDN から自動ダウンロード**します。そのため**初回はネットワーク接続が必要**で、
  読込に数十秒かかることがあります（2 回目以降はブラウザキャッシュにより高速化）。
- 完全オフラインで動かしたい場合は、言語データと WASM を `public/` 等に同梱し、
  `createWorker` の `langPath` / `corePath` / `workerPath` を指定する方式へ変更してください
  （`src/services/ocrService.ts` 内で集約しているため、ここだけの修正で対応できます）。
- ライブカメラ（映像検査・撮影画像OCR）は HTTPS（または localhost）かつ対応ブラウザでのみ
  有効です（前述の「iPhone でカメラを使う手順」を参照）。非対応・不許可時は画像アップロードに
  フォールバックできます。
- **OpenCV.js** も初回はCDNからダウンロードします（前述「OpenCV.js について」）。失敗しても
  ガイド枠フォールバックで検査は継続します。

```
  main.tsx                  エントリポイント
```

**OCR処理 / 回答データ読込 / 正規化 / 照合 / 結果出力 / カメラ / 映像処理（輪郭検出・前処理）**を
それぞれ独立モジュールに分離しています。映像処理・カメラは OCR（`ocrService`）と疎結合です。

- **OCR処理 (`ocrService.ts`)**: `OcrService` インターフェースで抽象化。永続ワーカーで
  行ごとの高頻度OCRに対応。`createOcrService()` の戻り値を差し替えれば別エンジンへ移行可能。
- **正規化 (`normalize.ts`)**: 全角→半角・空白除去・記号除去・置換辞書で誤読/異体字を補正。
- **映像処理 (`vision.ts` / `preprocessPipeline.ts` / `opencvService.ts`)**: `vision.ts` は
  安定グレースケール化と行検出（OpenCV 非依存）。`preprocessPipeline.ts` は設定値で実適用する
  OCR前処理パイプライン（OpenCV があれば利用、無ければ JS フォールバック）。`opencvService.ts` は
  輪郭検出に OpenCV.js を使用し、読込失敗時はガイド枠にフォールバック。
- **照合 (`match.ts`)**: 期待値ごとに OCR 候補から最も近い行を選び段階判定。`matchExpectedLine`
  を映像検査の行ごと照合でも共用。
- **結果出力 (`resultOutput.ts`)**: データ生成（`build*`）と出力（`downloadJsonData`）を分離。
  1枚分・複数銘板の両方に対応し、PDF など別形式の exporter を追加しやすい構造。
- **カメラ/映像検査 (`cameraService.ts` / `useCamera.ts` / `useVideoInspection.ts`)**:
  ストリーム制御の純粋ロジックと React 連携を分離。`useVideoInspection` が表示ループ(rAF)と
  OCR検査ループ(setInterval)を独立管理し、行ごとOK確定・銘板(No)ごとの枚数カウント・
  全数完了までの進行を行う（内部の30FPS/2FPS負荷分離・検査ロジックは従来どおり維持）。

## 今後の拡張案

- **QRコード読取**: 銘板や検査票の QR から製番を取得し、回答データを自動選択。
- **PDF帳票出力**: 検査結果を PDF 帳票として出力（`resultOutput.ts` に exporter を追加）。
- **iOSアプリ化**: PWA 化または React Native / Capacitor 等によるネイティブアプリ化。
- **輪郭検出の高度化**: 透視変換（warpPerspective）による台形補正、検出の安定化（時間方向の平滑化）。
- **辞書補正の強化**: 現場で頻出する誤読パターンを蓄積し、置換辞書を充実。
- **類似度判定の改善**: 文字種重み付け・N-gram・読み（カナ）正規化・部分文字列マッチの高度化や、
  検出行と期待値行の対応付け（順序・重複）の高度化。
- **重複カウント防止**: 同一銘板の連続OKを検知して二重カウントを抑止（現状は運用で担保）。
- **Web Worker / OffscreenCanvas 活用**: 前処理・輪郭検出をワーカー化し、さらなる負荷分離。
